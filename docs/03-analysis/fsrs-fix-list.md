# FSRS 수정 목록

> 작성일: 2026-09-05  
> 기준: 하루 한 번 완료하는 학습 세션과 FSRS 장기 복습을 일치시킨다.

## P0 — 핵심 학습 흐름

- [x] **일일형 FSRS 설정으로 전환**
  - `enable_short_term: false`, 목표 기억률 90%, 장기 간격 fuzz 사용.
  - 신규 `외웠어요`가 10분 뒤 overdue로 남지 않도록 한다.
  - 기존 `learning` 카드는 다음 응답에서 `review`로 정상 전환되는지 검증한다.
  - 하루가 지난 뒤 신규 Good 카드가 전부 재등장하지 않는 통합 테스트를 둔다.

- [x] **빠른 훑기 → SRS 편입 카드 고립 수정**
  - `state='new'`로 저장된 편입 카드가 due와 신규 조회 양쪽에서 제외되는 문제를 해결한다.
  - 편입 후 다음 정규 세션에 실제로 등장하는 통합 테스트를 추가한다.
  - 편입 카드를 일일 신규 한도 안에서 일반 신규보다 먼저 출제한다.

## P1 — 일정 및 데이터 일관성

- [x] **카드 상태와 복습 로그를 단일 트랜잭션으로 저장**
  - `user_card`, `review_log`, 필요 시 `session` 카운터를 원자적으로 갱신한다.
  - 실패 시 Store의 `busy`가 반드시 해제되도록 `try/finally`를 적용한다.

- [x] **복습 우선 큐 보장 및 backlog 정책 결정**
  - 런타임 셔플이 overdue 우선순위를 없애는 문제를 수정한다.
  - due가 많은 날 신규 12개를 그대로 추가할지, 자동 감축할지 정책화한다.
  - due는 오래 밀린 순서로 전부 처리하고 신규만 셔플한다.
  - 총 예정량 `신규 한도 × 3`을 기준으로 신규를 점진 감축한다.

- [x] **Again 정책과 죽은 미니라운드 정리**
  - 일일형 정책에 맞춰 사용하지 않는 `pendingAgain/startAgainRound`와 관련 상태를 제거했다.
  - `아직이에요`는 같은 세션에 재출제하지 않고 FSRS가 정한 다음 due로 이월한다.
  - 문서·주석·테스트를 실제 동작과 일치시켰다.

- [x] **약점 복습의 FSRS 반영 정책 분리**
  - 미래 due 카드의 보강학습은 기존 FSRS 일정과 상태를 그대로 유지한다.
  - 이미 due인 카드와 scan 신규 편입만 정식 재스케줄한다.
  - `review_log.scheduling_applied`로 정식 복습(1)과 일정 비변경 복습(0)을 구분한다.

## P2 — 통계, 성능, 유지보수

- [x] 약점 화면의 `reveal_ms`를 정규 학습과 동일하게 카드 노출 → 최초 reveal로 측정한다.
- [x] 진행도 분자에도 `verified` 및 `deprecated=0` 필터를 적용한다.
- [x] 스캔/편입 통계를 `scan_result` 원천 데이터에서 날짜별로 집계한다.
- [x] 레벨 선택은 신규 범위만 제어하고 기존 due는 전 레벨 유지하며 UI에 안내한다.
- [x] 전체 ID 조회와 `NOT IN`을 제거하고 DB의 `NOT EXISTS`로 신규 여부를 판정한다.
- [x] 혼합 Again/Good·장기 공백 다일 큐와 실제 SQLite 롤백 실패 주입 테스트를 보강한다.
- [x] `ts-fsrs`를 최신 안정판 5.4.2(FSRS-6)로 올리고 기존 카드 호환성을 검증한다.
